# UCMS Roles & Permissions

## Roles

| Role | Description |
|------|-------------|
| `STUDENT` | Enrolled student. Submits and tracks own concerns. |
| `ADMIN` | University staff. Manages all tickets, responds, and views analytics. |

> **Admin provisioning:** ADMIN accounts are created and assigned the `ADMIN` role manually via the Supabase dashboard. There is no public registration endpoint for admins.

## Ownership Rules

- STUDENT can only access tickets where `ticket.user_id === currentUser.id`
- STUDENT can only view attachments and responses on their own tickets
- STUDENT must have a verified email to create tickets (LIMITED accounts are read-only)
- ADMIN can access all tickets regardless of `user_id`
- Only ADMIN can transition ticket status (`PENDING → IN_PROGRESS → RESOLVED → CLOSED`)
- Notifications are scoped to the receiving user — ADMIN has no notification inbox
- Only ADMIN can create, update, or delete categories
- A category cannot be deleted if any ticket references it

## Enforcement

### Role Storage
- `role` stored in **Supabase Auth user metadata** (`raw_user_meta_data.role`)
- Values: `STUDENT` | `ADMIN`
- Role must never be trusted from request body — always derive from JWT claims

### Spring Boot (API Layer)
- Supabase issues JWT on login; Spring Boot validates it on every request via **JWKS endpoint**
- A custom filter (`SupabaseAuthFilter`) extracts the JWT, verifies signature, and populates `SecurityContext`
- Role extracted from JWT claims (`raw_user_meta_data.role`)
- Route-level: `@PreAuthorize("hasRole('ADMIN')")` on admin-only endpoints
- Resource-level: ownership check in **service layer** (not controller) for STUDENT access

### Supabase Postgres (RLS — second layer)
- Row Level Security enabled on all tables
- `tickets`: STUDENT can only SELECT/INSERT rows where `user_id = auth.uid()`
- `attachments`: STUDENT can only SELECT/INSERT rows linked to own tickets
- `responses`: STUDENT can only SELECT rows linked to own tickets
- ADMIN role bypasses RLS via service role key (used only in backend, never exposed to client)

### Supabase Storage
- Bucket: `attachments`
- STUDENT can upload only to path `tickets/{ticket_id}/` where ticket belongs to them (verified via RLS policy on storage)
- ADMIN can read all paths
- Signed URLs generated by backend for secure viewing
